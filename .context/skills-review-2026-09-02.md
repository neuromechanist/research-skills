## 3. Figures plugin: state versus the new goal

The plugin was designed around "AI text is unreliable, overlay everything in SVG".
That premise is what the owner now wants to flip. Concrete blockers, in order of severity:

1. **Overlay labels render at 1 to 2.5 pt.** `overlay_labels.py` writes `font_size_pt` as a bare SVG
   `font-size` inside a pixel viewBox; at 89 mm width the shipped example produces 2.46 pt text.
   The plugin's own font validator blocks every documented configuration.
2. **Text is forbidden in every AI prompt** (`generate_figure.py:122` appends "No text, no labels" unconditionally;
   `BASE_STYLE` in `generate_icon.py` does the same) and the hard-ceiling section in ai-full-figure says AI text is unreliable "as of 2026".
   There is no verbatim-text mode, no OCR, and no VLM legibility check.
3. **The bible has no entry point.** `theme.schema.json` exists, only `generate_figure.py` reads it,
   `generate_icon.py` has no `--theme` flag, nothing validates a theme, nothing scaffolds one,
   and `references/cell-theme.json` cited in the skill does not exist.
4. **Four disjoint palettes.** Okabe-Ito in the QA allow-list, Tol in the docs, navy/terracotta in svg-primitives and the icon examples,
   a fourth in `icon-templates.json`. Running `check_svg.py --palette okabe-ito` on the plugin's own default output fails.
5. **No multi-panel AI path.** A 2x2 with AI panels is roughly twelve manual invocations,
   two hand-written JSON files, and a step where a human hovers the mouse in Preview to read pixel coordinates.
6. **No iterate loop.** QA returns markdown only, has no JSON verdict, no max-iteration count,
   and no mapping from finding to regeneration action. Every generation skill says QA "runs proactively"; none dispatches it.
7. **QA is blind where it matters.** `check_raster.py` checks alpha corners, DPI, and dominant colors only.
   `check_svg.py` does not count `<image>` or `<path>` as shapes, so overlay figures report clean without inspection.
   No Type 3 font check, no venue-width check.
8. **Two drifting copies of the Codex/API backend** (icons and full-figure), hard-coded `gpt-image-2`,
   a single hard-coded `./output.png` output path whose temp dir is deleted on mismatch,
   silent size downgrade to 1024, no streaming, no retries, no candidate selection.
9. **Handoffs are inert.** About 55 `[[wiki-links]]` across the figures skills, an undefined `$FIGURE_QA_SCRIPTS`
   in four documented commands, and `Task(subagent_type: "figure-qa")` where Claude Code needs `Agent(subagent_type: "figures:figure-qa")`.
10. Trigger descriptions overlap: "make a figure" is a coin flip among scientific-figure, ai-full-figure, and svg-figure;
    the hard-ceiling clause in ai-full-figure reads as a positive trigger for the cases it forbids.
11. Tests: the 66-test svg-primitives suite is not in CI; nothing covers any AI path; eight `__pycache__` files are committed.

## 4. Proposed figures redesign (epic)

Goal: one conversational entry, bible first, parallel candidates, QA gate, bounded iteration.

### 4.1 Streamlined surface

Reduce seven skills to five plus the QA agent:

| Skill | Role |
| --- | --- |
| `figure` (new, orchestrator) | Routes by intent: bible, ai, vector, plot, compose. Owns the generate, QA, iterate loop. |
| `ai-figure` (merge of transparent-icons and ai-full-figure) | Codex or API backend, modes `icon`, `panel`, `figure`, `multipanel`, text rendering, reference conditioning. |
| `svg-primitives` (absorbs svg-figure as references) | Programmatic vector schematics; svg-figure's authoring conventions and editor handoff become references. |
| `plot-styling` | Unchanged role; reads the bible for palette and fonts. |
| `scientific-figure` | Composition and export only; reads the bible. |
| `figure-qa` agent | Same dispatch pattern, JSON verdict added, text and font checks added. |

### 4.2 Bible first

- New `figure` step 0: `init_theme.py` scaffolds `figures/theme.json` from a journal profile (Nature, Science, Cell, PNAS, poster, slide),
  optional seed colors, and optional reference images; `validate_theme.py` checks it against the schema.
- The theme becomes the single palette source. `check_svg.py` and `check_raster.py` accept `--palette theme.json`;
  svg-primitives, plot-styling recipes, and icon templates read colors and fonts from it.
- Theme gains `text` (headline size class, allowed word count per label, font family cue for the image model)
  and `layout` (panel grid, label style A/B/a/b) sections.

### 4.3 AI generation with rendered text

- One shared backend module (`plugins/figures/lib/image_backend.py`): preflight with a 10 s timeout on `codex --version`
  that reports quarantine and missing auth explicitly; `--model`, `--quality`, arbitrary sizes validated by the gpt-image-2 rules;
  glob-based output discovery; a log file the caller can tail; `--n` candidates; one retry; edit mode with a reference image.
- Prompt builder follows the Codex imagegen contract: `Text (verbatim): "..."` blocks with typography and placement,
  spell-out for uncommon tokens, quality high whenever text is present, bible tokens and negatives appended.
- Text policy rewritten as a ladder, not a ban: model-rendered text for titles, panel letters, and short labels
  (a configurable word cap, large relative size); overlay for dense labels, numerals, axes, equations;
  vector or plot skills for data.
- Transparency: when the backend is Codex, request a chroma-key background and let Codex's `remove_chroma_key.py` do the cutout;
  skip our threshold pass when the returned PNG already has alpha.
- Multi-panel: one `figure.json` spec describes panels, sizes, text, and shared references;
  the orchestrator generates panels in parallel with the same bible and a shared reference image for consistency,
  overlays only what the ladder assigns to overlay, composes with scientific-figure, and QAs the result.
  A single-shot multi-panel generation is allowed for posters and slides when the QA text check can verify panel letters.
- Fix the overlay unit bug (pt to user units via the mm/viewBox scale) so the overlay path is usable at all.

### 4.4 QA and iteration

- `check_raster.py` gains a text branch: OCR (tesseract via uv, VLM read-back as fallback), expected-versus-detected strings
  with edit distance, cap height measured in mm against the journal minimum, and a legibility score.
- `check_svg.py` treats `<image>` and closed `<path>` as shapes; a PDF branch flags Type 3 fonts and width over the venue text width.
- The QA report keeps its markdown and adds a JSON block: `status`, `findings[]` each with `check`, `severity`, `action`,
  and a `regenerate_hint` the orchestrator can paste into the next prompt or edit call.
- Loop contract in `references/iterate-loop.md`: generate N candidates in parallel, QA each in parallel,
  rank, pick, apply one targeted edit, re-QA, stop at pass or after `max_iter` (default 3), then report the best with its findings.
- Worker routing: candidate generation, QA, and OCR run on Sonnet-tier subagents in parallel;
  the orchestrating model does selection and the edit instruction.

### 4.5 Plumbing

- Replace every `[[link]]` with "invoke with the Skill tool as `figures:<name>`", fix `$FIGURE_QA_SCRIPTS`,
  namespace the agent dispatch, add `"agents": "./agents/"` to the Claude manifest so `agents/templates/` is not double-discovered.
- Rewrite the frontmatter descriptions as short, disjoint trigger sets with the routing rule in the description, not the body.
- Put the svg-primitives suite in CI, add a fake-backend seam so the AI path has offline tests, untrack `__pycache__`.
